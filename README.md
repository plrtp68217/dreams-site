# «СНЫ» — сценарий для разработки

Совместный редактор сценария игры: React (Vite + TypeScript) + FastAPI (SQLAlchemy, SQLite).

- **Авторизация** — логин/пароль, JWT. Первый зарегистрированный пользователь становится администратором.
- **Роли**
  | Роль | Может |
  |---|---|
  | Зритель (`viewer`) | читать сценарий, доску задач, историю и активность |
  | Команда (`editor`) | всё выше + править тексты разделов, создавать и править задачи, менять статусы, назначать исполнителей, создавать разделы, загружать картинки, откатывать версии |
  | Администратор (`admin`) | всё выше + выдавать роли, отключать учётные записи, сбрасывать пароли, удалять разделы и задачи |
- **Редактирование** — текст разделов пишется в Markdown с несколькими блоками для сценария (без HTML-тегов):
  ```
  > **Клоун:** Ты заказала это сама.          реплика
  > *Громкая связь:* Касса закрыта.           надпись / объявление
  ::: заметка Заголовок … :::                 заметка (ещё: нет-в-сценарии, записка, карточка,
                                              вводка, характеристики, выбор, этапы, дневник, плакаты)
  `ff_side_done`                              флаг
  ```
  В редакторе — кнопки для вставки блоков, шпаргалка, загрузка изображений и предпросмотр (его рисует сервер, так что он
  совпадает с сохранённым видом). Описания задач тоже пишутся в Markdown. Правки разделов и задач версионируются: если двое правят одно и то же, второй получит предупреждение о конфликте, а не молча затрёт чужой текст. Любую прошлую версию можно посмотреть и восстановить.
- **Задачи** — отдельно от текста сценария, нумеруются по порядку: `#1`, `#2`… У задачи есть название, описание (Markdown), тип (сценарий, геймдизайн, арт, программирование, звук, прочее), исполнитель и **место в сценарии**: раздел и, при желании, конкретная реплика, записка, заметка, заголовок или карточка. Исполнитель открывает задачу и одним кликом попадает в нужное место — оно подсвечивается.
  Создать задачу можно на доске («+ Новая задача») или прямо из текста: у реплик и других мест при наведении появляется «+ задача». Места, к которым уже есть задачи, помечены номерами задач.
- **Статусы**
  - задачи: Не начато → В работе → На проверке → Готово; доска задач с фильтрами по типу, разделу и исполнителю;
  - разделы: расписано полностью / есть концепт / восстановлено по скриншотам / нет в сценарии.
- **Активность** — у каждого участника команды график как на GitHub: год по дням, квадратик тем темнее, чем больше
  действий в этот день (шкала общая для всей команды). Ниже — лента всех изменений с фильтром по участнику.

## Запуск для разработки

Нужны Python 3.11+ и Node 20+.

```bash
# backend — http://127.0.0.1:8000 (документация API: /docs)
cd backend
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload

# frontend — http://127.0.0.1:5173 (проксирует /api и /media на backend)
cd frontend
npm install
npm run dev
```

При первом старте база `backend/dreams.db` заполняется сценарием из `backend/app/seed_data/scenario.json`
(доска задач при этом пустая), а картинки лежат в `backend/media/`. Затем откройте сайт и зарегистрируйтесь — вы станете
администратором.

Обновление старой базы (где задачи были карточками с кодами `FF-V01`, `LOC-FF-05`…) выполняется автоматически при старте:
карточки возвращаются в текст разделов, предложения и коды убираются, доска очищается; затем HTML разделов переводится
в Markdown. Перед каждым шагом рядом создаётся копия `dreams.before-<шаг>-<дата>.db`, а прежний текст разделов остаётся
в их истории версий.

## Тесты

```bash
cd backend && .venv\Scripts\python -m pytest --cov=app
cd frontend && npm test            # или npm run coverage
cd frontend && npm run typecheck
```

## Настройки backend

Переменные окружения (или файл `backend/.env`) с префиксом `DREAMS_`:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DREAMS_DATABASE_URL` | `sqlite:///backend/dreams.db` | любая БД, поддерживаемая SQLAlchemy |
| `DREAMS_SECRET_KEY` | генерируется в `backend/.secret_key` | ключ подписи токенов |
| `DREAMS_ALLOW_REGISTRATION` | `true` | `false` — пользователей создаёт только админ |
| `DREAMS_ADMIN_USERNAME` / `DREAMS_ADMIN_PASSWORD` | — | создать администратора при старте |
| `DREAMS_TOKEN_TTL_MINUTES` | `10080` (7 дней) | срок жизни входа |
| `DREAMS_CORS_ORIGINS` | `["http://localhost:5173", ...]` | если фронтенд на другом домене |

Обслуживание:

```bash
python -m app.cli create-admin <логин> <пароль>
python -m app.cli set-role <логин> viewer|editor|admin
python -m app.cli reseed      # стереть разделы/задачи и заново импортировать сценарий
```

## Структура

```
backend/
  app/            FastAPI: models, routers (auth, users, sections, tasks, activity, misc), seed, cli
  app/seed_data/  scenario.json — сценарий, извлечённый из старого сайта
  app/scenario_cleanup.py, app/migrations.py  перенос карточек в текст, удаление предложений, обновление старой БД
  media/          картинки (из старого сайта и загруженные)
  tools/import_legacy.py  повторный импорт legacy/index.html → seed_data + media
  tests/
frontend/
  src/api         клиент API и типы
  src/components  рендер сценария, карточки задач, редактор, история
  src/pages       страницы
  src/styles      scenario.css — стили исходного сайта, app.css — новый интерфейс
legacy/index.html исходный одностраничный сайт
```

Текст разделов хранится дважды: исходник в Markdown (`sections.source`, его правят) и HTML, который сервер рендерит
при сохранении (`backend/app/markup.py`). Сервер выдаёт каждой реплике, записке, заметке, заголовку и карточке скрытый `data-id` — на него ссылаются задачи
(поля `section` + `anchor`). В Markdown этих id не видно: при сохранении сервер переносит их со старой версии на новую,
сопоставляя места по тексту, так что правка реплики не отрывает от неё задачи. Старые внутренние ссылки вида `#ff-v01` продолжают работать — они ведут на нужную
страницу и прокручивают к месту. HTML очищается и на сервере (nh3), и в браузере (DOMPurify).
